# Text sources and distribution

## One intervention contract

[`prompts/intervention/prompt-full.md`](../prompts/intervention/prompt-full.md),
specifically its marked fenced block, is the canonical `prompt-v2.0` behavior
contract. The [integration guide](integration.md) describes installation, not
another protocol. Specialized variants and the manually maintained Spanish
translations must preserve that contract; neither is an independent authority.

Explanations, examples, and the human checklist follow the same two gates,
claim-specific evidence appraisal, optional credible alternatives, proportional
outputs, correction of the assistant's own errors, and high-stakes boundaries.
No-intervention cases answer normally, not in Light. No fixed source ladder,
category score, universal falsifiability rule, or label diagnosing the user
supersedes the canonical contract.

## Generated provenance and exact-copy exceptions

Generated region notices sit immediately **before** the start delimiter, never
inside copyable instructions. Whole-file portable Markdown gets a generated
source header after YAML and the behavior marker where present; other Markdown
gets it first. YAML remains the first block and `prompt-v2.0` keeps its required
position. The generator writes these notices, not a manual output edit.

Packaged intervention Markdown deliberately stays byte-identical to public
sources: CLI/API retrieval and CI compare entire files, not just instructions.
Those exact-copy outputs therefore use `.gitattributes` provenance rather than
an extra comment. Plain `.txt` prompts have no comment syntax and retain marker
plus exact prompt text; `LICENSE` and `NOTICE` also remain verbatim. These are
format/retrieval exceptions, not permission to hand-edit generated files.
All generated paths, including partially generated root/skill wrappers, are
marked `linguist-generated` in [`.gitattributes`](../.gitattributes). That is a
file-level display hint; it does not make maintained wrapper prose generated.
Manual diagnostic cards/catalogs are intentionally not marked generated.

## Skill metadata and compatibility

The [Agent Skills specification](https://agentskills.io/specification) requires
parseable YAML, a nonempty description of at most 1,024 characters, and a
1-64-character lowercase hyphenated `name` matching the parent directory.
CI's offline suite validates both entry points against these constraints.

The portable `skills/baloney-detection-kit/SKILL.md` fully satisfies the checked
naming constraints. The one explicit compatibility exception is
`skill/SKILL.md`: its retained `name: baloney-detection-kit` does **not** match
the legacy directory `skill`. Tests pin this exact path/name exception rather
than skipping name matching for arbitrary directories. Renaming that public
path or changing the installed skill identity would break the promised 3.x
compatibility. Use the complete portable directory for spec-conforming
installation. Both frontmatters still undergo YAML, length, and name-syntax
validation; this is not a claim that the legacy layout fully conforms.

## Offline coherence, scope, and version review

`tests/test_document_coherence.py` checks Git-inventoried distributed Markdown,
including examples, templates, validation guidance, and generated mirrors.
It excludes authored `essay/`, `posts/`, `research/diagnosis-paper/`, historical
`docs/plans/`, `CHANGELOG.md`, `validation/**/artifacts/`, and every `results/`
tree. It recognizes explicit rejected bad-response quotations and sentence-level
negations, rather than banning words such as "alternatives" or "unfalsifiable".
Focused synthetic fixtures cover each obsolete prescription and its legitimate
counterexample. This is a regression tripwire for known contradictions, not a
general semantic proof; review context and the canonical source when extending it.

Run the six [required checks](../CONTRIBUTING.md#required-checks), including the
complete nonintegration suite and `python scripts/sync_prompts.py --check`.
Existing CI runs the coherence and metadata tests on every supported Python
version. Synchronization checks copy integrity; the coherence test checks
different documents for known contradictory prescriptions.

This phase aligns explanations and generated provenance, not the behavioral
contract: canonical/specialized instruction bodies, gates, modes, outputs, and
boundaries remain unchanged, so no `prompt-v2.0` bump or behavior changelog entry
is warranted. The human checklist already used qualitative calibration and
non-diagnostic labels at the audit baseline; it was not rewritten again.
Prior maintainer behavior/version and translation approvals remain human gates,
not approvals supplied by these offline checks. Phase-two packaging/restructuring,
live validation, releases, and repository settings are outside this phase.
